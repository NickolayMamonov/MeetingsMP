Запусти полный автоматический цикл разработки MeetingsMP:

## Шаги цикла

1. **FETCH**: Найди следующий открытый Issue с меткой `agent-task`
   ```
   gh issue list --label agent-task --state open --limit 5
   ```
   Выбери первый, прочитай его содержимое и issue template

2. **CHECK PLAN**: Проверь, есть ли в Issue существующий план (комментарий с чеклистом шагов)

3. **PLAN** (если нет): Вызови `@plan` для проектирования решения
   - Передай Issue, контекст, затронутые модули
   - Дождись плана с разбивкой на шаги

4. **BRANCH**: Создай feature-ветку
   - Формат: `feature/<issue-number>-<short-slug>`
   - Используй `git worktree add` для изоляции

5. **BUILD**: Реализуй задачу
   - **Сложная задача** (архитектура, expect/actual, новый модуль) → `@developer-complex`
   - **Простая задача** (багфикс, UI-правки, конфиг) → `@build`
   - Передай план, Issue, ожидаемые затронутые файлы

6. **REVIEW**: Вызови `@review` для проверки
   - При замечаниях — вернись к шагу 5 (developer должен исправить строго по списку)
   - Повторять до APPROVE

7. **CI/CD**: Вызови `@ci-cd` для финальной проверки и создания PR
   - Гейт: detekt + desktopTest + testDebugUnitTest + assembleDebug
   - PR откроется только при зелёном гейте

8. **REPORT**: Краткий отчёт о результате:
   - Issue, ветка, номер PR, статус гейта, вердикт ревью

## Важно
- Мерж PR делает ТОЛЬКО человек (CODEOWNERS)
- При любой ошибке — анализируй и передавай разработчику на исправление
- Не бери больше одной задачи одновременно
- Отслеживай прогресс через `todowrite`
