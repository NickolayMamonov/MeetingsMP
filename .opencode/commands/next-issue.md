Возьми Issue с меткой `agent-task` из GitHub бэклога MeetingsMP и спроектируй решение.

Аргумент (опционально): номер Issue. `$ARGUMENTS`

## Что сделать

1. **FETCH**:
   - Если передан номер (`$ARGUMENTS` не пуст) — бери именно этот Issue:
     ```
     gh issue view $ARGUMENTS
     ```
   - Иначе — возьми **самый старый** открытый Issue с меткой (наименьший номер):
     ```
     gh issue list --search "label:agent-task state:open sort:created-asc" --limit 50
     ```
     и выбери **верхний** в списке (он самый старый).

   **Правило очерёдности (важно):** если номер не задан явно, всегда бери самый старый open
   Issue. Порядок задач критичен — задачи нумерованы по шагам, и поздний шаг нельзя начинать
   раньше раннего (например, Шаг 2 «аутентификация» нельзя раньше Шага 1 «контрактные блокеры»,
   иначе рефакторинг ляжет на ещё не исправленный baseline).

2. **ANALYZE**: Прочитай Issue полностью:
   - Тип задачи (UI / бизнес-логика / рефакторинг / инфраструктура / багфикс)
   - Цель и контекст
   - Затронутые модули
   - Критерии приёмки
   - **Зависимости:** если в теле есть «Блокируется #N» / «Blocked by #N» — проверь через
     `gh issue view N`, что #N уже закрыт (в мерже). Если #N ещё открыт — НЕ начинай этот Issue,
     сообщи пользователю, что сначала нужно завершить #N.

3. **PLAN**: Вызови `@plan`.
   Передай ему Issue, контекст, затронутые модули. `@plan` создаст:
   - Анализ требований и декомпозицию
   - Архитектурное решение
   - План реализации с разбивкой на шаги
   - Критерии приёмки для каждого шага

4. **COMPLEXITY**: Определи уровень сложности:
   - **СЛОЖНАЯ** (новый модуль, expect/actual, архитектура, DI) → `@developer-complex`
   - **ПРОСТАЯ** (багфикс, UI-правки, конфиг) → `@build`
   - Если не уверен — считай сложной.

5. **REPORT**: Выведи итог:
   - Номер Issue и заголовок
   - Сложность и выбранный разработчик
   - Краткое саммари плана (3-5 пунктов)
   - Зависимости проверены? (все блокирующие Issue закрыты — Да/Нет)
   - Готово к реализации? (Да/Нет — если есть открытые вопросы, перечисли их)

Не начинай кодить — только анализ и план.
