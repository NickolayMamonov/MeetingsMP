Возьми следующий открытый Issue с меткой `agent-task` из GitHub бэклога MeetingsMP и спроектируй решение.

## Что сделать

1. **FETCH**:
   ```
   gh issue list --label agent-task --state open --limit 5
   ```

2. **ANALYZE**: Прочитай Issue полностью:
   - Тип задачи (UI / бизнес-логика / рефакторинг / инфраструктура / багфикс)
   - Цель и контекст
   - Затронутые модули
   - Критерии приёмки

3. **PLAN**: Вызови `@plan`
   Передай ему Issue, контекст, затронутые модули. `@plan` создаст:
   - Анализ требований и декомпозицию
   - Архитектурное решение
   - План реализации с разбивкой на шаги
   - Критерии приёмки для каждого шага

4. **COMPLEXITY**: Определи уровень сложности:
   - **СЛОЖНАЯ** (новый модуль, expect/actual, архитектура, DI) → `@developer-complex`
   - **ПРОСТАЯ** (багфикс, UI-правки, конфиг) → `@build`
   - Если не уверен — считай сложной

5. **REPORT**: Выведи итог:
   - Номер Issue и заголовок
   - Сложность и выбранный разработчик
   - Краткое саммари плана (3-5 пунктов)
   - Готово к реализации? (Да/Нет — если есть открытые вопросы)

Не начинай кодить — только анализ и план.
