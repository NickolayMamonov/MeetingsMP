Проведи ревью изменений в текущей ветке MeetingsMP или открой PR и вызови `@review`.

## Что сделать

1. **CONTEXT**: Определи, что ревьюить:
   - Если есть открытый PR → читай его через `gh pr view`
   - Если нет PR → смотри незакоммиченные изменения через `git diff`

2. **REVIEW AGENT**: Вызови `@review` с контекстом:
   - Номер Issue и PR (если есть)
   - Дифф изменений
   - План реализации (из Issue комментария)
   - Ожидаемые критерии приёмки

3. **VERIFY**: `@review` запустит:
   - `git diff` / `git log` для анализа изменений
   - `./gradlew detekt` для статического анализа
   - `./gradlew desktopTest` и `testDebugUnitTest` для проверки тестов
   - `./gradlew assembleDebug` для проверки сборки

4. **VERDICT**:
   - **APPROVE**: можно переходить к CI/CD → используй `@ci-cd`
   - **REQUEST_CHANGES**: есть критичные блокеры → вызови `@build` с инструкцией «исправить эти замечания»
   - **APPROVE_WITH_SUGGESTIONS**: можно мержить, но есть рекомендации

5. **REPORT**: Выведи вердикт и список замечаний
